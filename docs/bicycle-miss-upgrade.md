# 정지 자전거 누락 개선 기록

같은 197장에 대해 기존 검출 115장에서 현재 프레임 재검출 포함 134장으로 검출 수가 증가하였다. 선택적 영상 보정까지 활성화한 시험에서는 모델 검출 136장과 영상 추정 29장으로 총 165장에 박스를 출력하였다. 영상 추정은 YOLO 검출률에 합산하지 않는다. 운영 서버의 모델 교체·재시작과 실제 백엔드 패치 적용은 수행하지 않았다.

## 누락 원인

이전 1280 one-to-many 주 모델과 640 보조 모델 조합의 누락 82장을 분석하였다. 대상 자전거와 IoU 0.3 이상으로 겹친 원시 후보를 기준으로, 82장 모두 자전거 점수가 0.35 미만이었다. 79장에서는 사람 점수도 0.1 미만이었다. 기존 재검사에 필요한 사람 후보가 없어 자전거 영역을 다시 검사하지 못하는 경우가 확인되었다.

최고 점수 후보 class는 `person` 48장, `bicycle` 22장, `traffic light` 4장, `traffic sign` 5장, `skateboard` 3장이었다. 이는 모델의 후보 분류이며 실제 객체의 정체를 의미하지 않는다. 근거는 `result/bicycle-upgrade/miss-diagnostics.json`이다.

## 검출 경로 변경

1. 기존 주 모델·보조 모델 검출을 수행한다. 이미 자전거가 검출된 위치의 중복 분류 보정은 생략한다.
2. 같은 카메라에서 최근 검출한 자전거 위치를 별도 후보로 사용한다. 사람 후보가 없어도 현재 프레임의 보조 모델로 재검사한다.
3. 재검사에서 자전거 점수 0.55 이상, 이전 박스와 IoU 0.4 이상이며 겹친 사람 검출 근거가 없으면 현재 모델 검출로 추가한다. `detectionSource=ROI_REDETECTION`으로 표시한다.
4. 모델이 확인하지 못한 경우 영상 보정이 활성화되어 있을 때만 이전 영상과 비교한다. 같은 위치 주변 3픽셀 범위에서 정규화 상관 점수 0.85 이상이고 마지막 모델 확인 후 2초 이내이면 `VISUAL_TRACKER`로 표시한다.

영상 일치만으로는 마지막 모델 검출 시각을 갱신하지 않는다. 무늬가 거의 없는 영역은 보정 템플릿으로 저장하지 않는다. 추가 영역 추론은 프레임당 최대 4회, 저장 자전거는 카메라당 최대 20개로 제한한다. 다른 해상도의 프레임으로 변경되면 기존 템플릿을 사용하지 않는다.

통합·객체 전용 서버가 카메라별 상태를 검출기에 전달한다. 복구 후 현재 구역·트램 정책을 적용하고 객체 ID 및 `ENTER`·`STAY` 등을 계산한다. 영상 보정은 자전거에 한정하며 사람의 쓰러짐 판정에는 사용하지 않는다. 단기 영상 보정의 2초 제한은 기존 객체 ID 유지 정책과 별개이다.

## 197장 검증 결과

| 구성 | 기존 검출 경로 | 현재 프레임 영역 재검출 | 영상 추정 | 누락 |
|---|---:|---:|---:|---:|
| 이전 프레임별 검출 | 115 | 0 | 0 | 82 |
| 새 기본 모드 | 115 | 19 | 0 | 63 |
| 영상 보정 활성화 시험 | 115 | 21 | 29 | 32 |

새 기본 모드는 현재 프레임 모델로 확인된 134장만 출력한다. 영상 보정 활성화 시험에서는 직전 프레임의 위치를 다음 프레임에서 다시 검사할 수 있어 영역 재검출 결과가 기본 모드와 다를 수 있다.

영상 보정 시험은 197장을 촬영 파일명의 시간 순서로 처리하였고, 파일명에 포함된 촬영 시각 차이로 2초 제한을 검증하였다. 실제 서비스는 처리 시점의 단조 증가 시계를 사용한다. 순차 처리 전체 결과는 `result/bicycle-upgrade/sequence-results.jsonl`, 집계는 `sequence-summary.json`에 기록하였다. 평균 CPU 검출기 처리 시간은 약 905ms이며 파일 읽기·HTTP·callback·대기열을 제외한다. GPU 실시간 성능으로 해석하지 않는다.

기본 모드는 같은 실행의 기존 검출 출력을 입력으로 복구 단계만 재실행하여 검증하였다. `result/bicycle-upgrade/default-recovery-replay.json`에 결과를 기록하였으며, 이 재실행으로 전체 처리 시간을 추정하지 않았다.

전체 데이터는 기존 박스·글자가 포함된 동일 장면의 사진이다. 다른 카메라·동물·이동수단 전체의 성능이나 실제 영상 오탐률로 일반화하지 않는다. 최초 검출 이전의 객체와 긴 미검출 구간은 복구하지 못할 수 있다. 비교 이미지는 `result/bicycle-upgrade/recovery-comparison.jpg`이다.

## 백엔드 전달 필드

기존 검출 결과는 출처 필드가 없을 수 있으며, 이 경우 기존 모델 검출 경로로 해석한다. 복구 결과에는 다음 선택 필드를 포함한다.

| 필드 | 의미 |
|---|---|
| `detectionSource=ROI_REDETECTION` | 현재 프레임을 보조 모델로 재검출한 결과. `confidence`는 현재 모델 점수이다. |
| `detectionSource=VISUAL_TRACKER` | 영상 일치 기반 추정. `confidence`는 마지막 모델 검출 점수이다. |
| `visualTrackingScore` | 현재 프레임과 이전 검출 영상의 상관 점수. YOLO 확률이 아니다. |
| `detectionAgeSeconds` | 마지막 모델 확인 이후 경과 시간. 영상 보정에서는 0~2초이다. |

```json
{
  "class": "bicycle",
  "confidence": 0.3666,
  "bbox": [1007, 276, 1037, 329],
  "zoneLevel": "safe",
  "zoneName": "safe-default",
  "detectionSource": "VISUAL_TRACKER",
  "visualTrackingScore": 0.9681,
  "detectionAgeSeconds": 1.012
}
```

위 예시는 검증 실행의 객체 결과이며, 실제 callback에서는 기존 구역·트램·추적·이벤트 필드가 추가될 수 있다. AI callback의 객체 필드 허용 목록에 세 선택 필드를 추가하였다.

현재 백엔드의 `readDetectedObject`가 새 필드를 제거하는 것을 확인하였다. 영상 추정이 직접 검출로 오해되지 않도록 `OBJECT_VISUAL_RECOVERY` 기본값을 `0`으로 설정하였다. 현재 프레임 영역 재검출은 기본 사용하며, 영상 보정은 백엔드 필드 보존을 반영한 뒤에만 활성화한다.

백엔드 수정안은 [backend-bicycle-recovery.patch](backend-bicycle-recovery.patch)에 기록하였다. 적용 대상은 객체 타입, 응답 정규화 함수, 관련 단위 테스트이다. 실제 백엔드는 현재 쓰기 허용 경로 밖에 있어 변경하지 않았다. 별도 복사본에서 관련 테스트 14개 통과와 실제 소스에 대한 `git apply --check`를 확인하였다. 적용 후 백엔드의 기존 prebuild 절차로 TSOA 스펙·라우트를 재생성하고 관련 테스트 및 통합 빌드를 수행한다.

```bash
# 백엔드 필드 보존 반영 이후 AI 서버에 설정한다.
OBJECT_VISUAL_RECOVERY=1
```

통합 서버의 `--object-visual-recovery`, 객체 전용 서버의 `--visual-recovery`도 같은 기능을 활성화한다. 기본 모드에서는 영상 추정 결과를 전달하지 않는다.

## 검증 범위

관련 Python 테스트 106개가 통과하였으며, HTTP 연결 테스트 1개는 실행 환경의 소켓 제한으로 제외하였다. 백엔드 수정안의 관련 테스트 14개는 별도 복사본에서 통과하였다.

자전거 소실·가림·다른 영상·저대비 영역·보정 만료·카메라 상태 분리·추론 횟수 제한·동일 ID와 `STAY`·현재 구역 재판정·callback 필드 보존을 회귀 테스트로 확인하였다. 실제 보조 모델을 사용한 합성 소실·가림 대조군 2개에서는 복구 박스가 발생하지 않았다. 이는 실제 영상의 오탐률 측정은 아니다.

실제 운영 서버 배포, GPU 지연 시간·처리량, 백엔드 실서버 반영·통합 빌드는 미검증 상태이다. 남은 초기 검출·긴 누락 개선에는 깨끗한 원본 영상과 여러 장면의 전체 객체 라벨을 확보한 추가 모델 검증·학습이 필요하다.
