# 기존 시스템 기반 KPI 개선 조사

## 조사 결과

기존 FT3 검출 모델, FT4 학습 결과, 사람 검출 유지·자전거 복구·구역·추적·쓰러짐 판정 코드, 운영 DB의 실제 검출 결과와 현장 시험 사진을 확인하였다. 기존 모델을 기준으로 FT4 교체, 화면 분할, 낮은 점수 관측 유지, 위치 재검출을 시험하였다.

이번에 적용한 변경은 원본 평가 입력 보존과 쓰러짐 이벤트 집계 보완이다. 비교한 검출 후보는 개선 근거가 부족하여 운영에 반영하지 않았다. 1차년도 성능 목표의 달성 여부는 아직 판정하지 않는다.

## 원본과 분석 사진의 차이

현재 백엔드는 촬영 프레임을 분석 폴더에 복사한 뒤, 분석 결과를 받아 해당 사진에 얼굴 모자이크와 검출 박스·글자를 추가한다. `analysis-export`의 사진은 이 처리 결과이다. 이를 모델 입력으로 재사용하면 운영 중 실제 입력과 달라진다.

새로 보존한 원본 453장 중 카메라별 12장씩 총 96쌍을 같은 FT3 모델과 같은 임계값으로 비교하였다. 두 입력은 파일명이 같은 촬영 프레임과 그 분석 사진이며, 비교 당시의 파일을 각각 보존하고 SHA-256을 기록하였다.

| 출력 클래스 | 원본 입력의 출력 박스 | 분석 사진 입력의 출력 박스 | 양쪽 출력의 일대일 일치 수(IoU ≥0.5) |
|---|---:|---:|---:|
| 사람 | 1,108 | 593 | 578 |
| 자전거 | 222 | 137 | 105 |
| 트럭 | 12 | 16 | 9 |
| 동물 | 8 | 0 | 0 |
| 승용차 | 12 | 0 | 0 |

위 수치는 모델 출력의 차이이며 정답 대비 정확도·Recall이 아니다. 원본의 1,108개 사람 박스를 모두 정답으로 간주하지 않는다. 같은 모델에서도 원본과 분석 사진의 결과가 크게 달라지므로, 분석 사진 재추론 결과만으로 운영 모델 교체나 임계값 변경을 결정할 수 없다.

10월 21일 카메라 33의 기존 진단 구간도 확인하였다. DB에 저장된 실제 분석 결과에서는 대상과 겹치는 사람 박스가 A 구간 11/42장, B 구간 11/13장에 있었다. 현재 모델로 분석 사진을 재추론하면 각각 35/42장, 2/13장으로 달라졌다. 과거 실행의 모델 해시·설정 전체가 해당 DB 행에 보존되어 있지 않아 그 차이를 전부 사진 처리의 영향으로 단정하지 않는다.

## 후보별 시험 결과

| 후보 | 실행 결과 | 판정 |
|---|---|---|
| FT4 눕기 모델 교체 | 기존 진단 창의 대상 검출이 A 35/42→6/42, B 2/13→1/13. 일반 사진 306장의 기존 FT3 사람 출력 유지율 74.7%, 자전거 26.6% | 교체 제외 |
| FT3 화면 4분할 추가 검출 | A 35/42→35/42, B 2/13→4/13. 오프라인 검출 처리시간 평균 26.5→133.3ms | 개선 폭 대비 처리비용이 커 반영 보류 |
| 확인된 사람의 관측 유지 점수 0.35→0.20/0.15 | B 대상 검출 2/13 유지, 대상 쓰러짐 시작 이벤트는 생성되지 않음 | 해당 누락의 해결책으로 채택하지 않음 |
| 최근 확인된 위험구역 사람의 위치 재검출 | 기존 임계값·위치 일치·확인 유효시간을 유지하였으나 대상 검출 개선 없음 | 반영 보류 |
| 가로 사람 박스의 회전 입력 재검출 | 대상 검출·대상 쓰러짐 시작 이벤트 개선 없음 | 반영 보류 |

검출 수는 기존 진단 박스와 IoU ≥0.3으로 비교한 결과이다. A 구간 42장에는 눕기 전·후의 전이 자세가 일부 포함되어 있어 정식 눕기 GT로 사용하지 않는다. 두 구간의 표본을 확인한 결과 B 구간은 대부분 기존 박스·글자가 포함된 입력이었다. 일반 사진 306장의 기준도 FT3 자체 출력이므로 위 유지율은 Precision·Recall을 뜻하지 않는다.

낮은 점수 유지와 위치 복구 시험은 두 시험 구간 및 운영 사진 748장, 총 848장의 모델 후보를 촬영시각 기준으로 재생하였다. 모델 후보 자체가 없는 프레임은 단순 점수 완화만으로 복구되지 않았다. 시간 기준 재생 결과를 실시간 처리율이나 전체 이벤트 정확도로 보고하지 않는다.

## 구현 및 검증 경로

### 원본 보존

`capture_evaluation_frames.py`는 기존 촬영 폴더에서 새 JPEG를 읽어 별도의 평가 폴더에 보존한다. 파일이 읽는 도중 변경되거나 JPEG 종료 표시가 없으면 보존하지 않으며, 원본과 기존 출력 파일을 덮어쓰지 않는다. 파일별 카메라·경로·바이트·해시·복사시각을 `manifest.jsonl`에 기록한다.

```bash
python capture_evaluation_frames.py /upload/visit_servant/frames \
  --seconds 30 --output result/kpi/new-raw-evaluation
```

실행 결과는 원본 453장, 122,523,740바이트이다. 카메라별 건수는 1번 60장, 2번 59장, 3번 35장, 4번 57장, 5번 60장, 6번 62장, 7번 60장, 8번 60장이다. 이 건수는 보존에 성공한 파일 수이며 센서의 전체 생성 프레임 수나 드롭률이 아니다. 해당 표본에는 검토된 위험 이벤트 GT가 없다.

### 독립 쓰러짐 이벤트 집계

기존 평가는 `행동=ENTER/ESCALATE`만 선택하여 구역 체류(`STAY`) 중 새로 발생한 쓰러짐을 집계하지 못하였다. `--event-type fall`을 추가하여 `쓰러짐이벤트=ENTER`를 별도로 평가한다. 기본 구역 평가는 기존 방식대로 유지한다. 쓰러짐 열이 없는 이전 export를 쓰러짐 평가에 넣으면 오류로 중단한다.

```bash
python evaluate_kpi.py result/kpi/live-20261027-121700/*.xlsx \
  --event-type fall --output result/kpi/fall-candidates.json
```

위 명령은 분석 후보의 집계이다. 실제 시스템 경보 성능을 평가할 때는 선택한 유형의 실제 경보 CSV(`--alerts`)와 해당 유형의 검토 완료 GT·평가 구간(`--gt`, `--coverage`)이 필요하다. `scenario=normal/occluded`는 가시성 구분이며 구역·쓰러짐 유형과 별개이다.

## 다음 개선 대상

1. 방금 추가한 원본 보존 경로로 위험구역 진입·체류·눕기·숙이기·겹침과 비위험 통과를 수집한다. 구역 밖 객체와 실제 위험을 함께 검토하여 Precision·FPR의 분모를 확보한다.
2. 원본의 대상·구역·시작·끝을 사람이 검토한 뒤 기존 최종 경보 기록과 매칭한다. 일반 구역 이벤트와 독립 쓰러짐을 나누어 누락 원인을 집계한다.
3. 누락을 검출 후보 부재, 점수 기각, 추적 단절, 구역 판정, 트램 접근 조건으로 구분한다. 원인이 확인된 단계만 수정한다. 현재 FT4나 임계값을 전체 적용하여 출력 수만 늘리지 않는다.
4. 학습이 필요한 경우 원본 입력을 사용하고 촬영 회차·시간대를 분리한다. 현재 학습 자료의 자체 라벨과 분석 사진은 독립 검증 자료로 취급하지 않는다.

위 순서가 현재 보유 자산으로 진행할 수 있는 개선 경로이다. 이번 조사에서 새 검출 후보가 1차년도 목표를 달성한다는 근거는 확보되지 않았다.
